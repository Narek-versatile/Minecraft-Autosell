# Minecraft 26.2 — API notes

**26.2 is past the model training cutoff and renamed a great deal.**
Recalling 1.21.x names will produce code that does not compile, or worse,
compiles against something that no longer means what you think.

**Verify everything with `javap` against the real client jar:**

```
JP=~/Library/Application\ Support/ElyPrismLauncher/java/java-runtime-epsilon/bin/javap
J=~/Library/Application\ Support/ElyPrismLauncher/libraries/com/mojang/minecraft/26.2/minecraft-26.2-client.jar
"$JP" -cp "$J" net.minecraft.client.Minecraft | grep -i screen
```

`javap -p -c` gives bytecode, which is how several of the bugs in
`BUG-HISTORY.md` were actually diagnosed. It is worth the effort.

## 26.2 ships DEOBFUSCATED

This is the single most important fact about building for this version.

- Yarn mappings stop at **1.21.11**
- Intermediary stops at **1.21.11** (26.2 returns a stub `0.0.0`)
- Mojang publishes **no `client_mappings`** in the 26.2 version JSON
- The client jar contains real names: `net/minecraft/client/Minecraft.class`,
  `com/mojang/blaze3d/Blaze3D.class`, ~10,950 classes

Therefore **`build.gradle` has no `mappings` dependency and must not gain
one.** This matches the official `fabric-example-mod` branch `26.2`, which
is the authoritative reference:
https://github.com/FabricMC/fabric-example-mod/tree/26.2

## Renames that affect this mod

| Old (≤1.21.x) | 26.2 |
|---|---|
| `ClickType` | `ContainerInput` |
| `handleInventoryMouseClick(...)` | `handleContainerInput(int, int, int, ContainerInput, Player)` |
| `mc.screen` (field) | `mc.gui.screen()` — screens moved to `Gui` |
| `mc.setScreen(s)` | `mc.gui.setScreen(s)` / `mc.setScreenAndShow(s)` |
| `ResourceLocation` | `Identifier` (`net.minecraft.resources.Identifier`) |
| `ResourceKey.location()` | `ResourceKey.identifier()` |
| `GuiGraphics` | `GuiGraphicsExtractor` |
| `Screen.render(...)` | `Screen.extractRenderState(GuiGraphicsExtractor, int, int, float)` |
| `Renderable.render` | `Renderable.extractRenderState` |
| `KeyboardHandler.keyPress(long,int,int,int,int)` | `keyPress(long window, int action, KeyEvent event)` |
| `Screen.keyPressed(int,int,int)` | `keyPressed(KeyEvent)` |
| `Options.hideGui` | gone — no direct equivalent used |
| `player.displayClientMessage` | gone — use `mc.gui.chatListener().handleSystemMessage(c, false)` |

## Crafting is server-authoritative

`InventoryMenu.slotsChanged` delegates to
`CraftingMenu.slotChangedCraftingGrid(..., ServerLevel, ...)`. It takes a
**ServerLevel**, so the client never computes a crafting result. The result
slot stays empty until a `ClientboundContainerSetSlot` arrives.

Consequence: an empty result while the grid holds ingredients means the
round trip has not completed. Treating that as "nothing to craft" caused a
visible wobble — see `BUG-HISTORY.md` #6.

## Container clicks carry a stateId

`ServerboundContainerClickPacket` includes `stateId`. Two clicks issued in
the same tick are stamped with the same id; the server processes the first,
advances state, then treats the second as stale and resyncs the container,
reverting it.

**One container click per tick on the player inventory menu.** Chest
transfer loops get away with bursting only because they re-scan and retry.

## Baritone for 26.2

No prebuilt release exists. Branch `26.2` of
https://github.com/cabaletta/baritone targets exactly
`minecraft_version=26.2`, `fabric_version=0.19.3`, `java_version=25`.

```
git clone --depth 1 -b 26.2 https://github.com/cabaletta/baritone
cd baritone
./gradlew :fabric:build -x proguard -x test
# -> fabric/build/libs/baritone-fabric-1.18.0.jar
```

`-x proguard` is **required**: upstream's ProGuard step needs a full JDK
with `jmods`, and the Prism-managed runtime is a JRE bundle. That step is
only release minification, so skipping it is harmless.

Baritone is LGPL-3.0. It is used as a **separate installed mod reached by
reflection only** (`BaritoneWalker`), never linked at compile time, so its
licence does not reach this mod.
